Executive Project Summary

This project implements a concurrent encryption service tailored for embedded real-time systems using QNX Neutrino 8.0 on a Raspberry Pi 4B. By breaking large data blocks into discrete Segments, tasks are distributed to a pre-warmed Worker Pool while the microkernel server uses deferred message replies to keep the channel responsive without blocking.

🎯 Tested Hardware Profile

  • Board: Raspberry Pi 4 Model B (Rev 1.4)
  • Processor: Broadcom BCM2711, 4× Cortex-A72 @ 1.5 GHz
  • OS: QNX Neutrino RTOS 8.0.3 (aarch64le)
  • Network: Direct Ethernet peer-to-peer at 10.0.0.1
  • Memory: 4 GB LPDDR4, RAM-disk at /dev/shmem

✨ Concurrency Highlights

  • Parallel CTR: Dynamic block counter arithmetic per segment.
  • Thread Safety: Scratchpad encryption + single commit memcpy.
  • Multi-client Interleaving: Multiple PIDs served concurrently.
  • Client Responsiveness: Main thread unblocked while sender waits.
  • Clean Teardown: Safe handling of Abandoned Jobs (ESRCH).

QNX Microkernel Architecture & Message Flow

Explore the detailed thread interaction, zero-copy memory pulling, and synchronization barriers between encclient and encserver.

Interactive Message Passing & Concurrency Pipeline

Synchronization: Workers encrypt in private memory; lock job.mutex only for 1 memcpy. 🔔 Signaling: Last completed worker signals job.done_cv to wake Coordinator.

Zero-Copy MsgRead() Offset Pull

Instead of allocating a massive receive buffer for MsgReceive(), the server receives only the 8-byte encsvc_request_t header. After checking size validity, it calls MsgRead(rcvid, buf, len, sizeof(req)), pulling data directly into the allocated job buffer.

Deferred MsgReplyv() Architecture

Documented in ADR 0001. By retaining rcvid and replying from the detached coordinator thread, the server avoids two-phase polling (GET_RESULT) while preserving full server availability for incoming client jobs.

Parallel CTR Counter Derivation

AES-CTR turns a block cipher into a stream cipher by encrypting successive counter values. Each segment starts at counter IV + (offset / 16). Because blocks don't depend on preceding ciphertext, workers encrypt completely in parallel.

Diagnostic Field Guide & Troubleshooting Matrix

Every documented failure mode encountered during testing on the Raspberry Pi 4B with immediate, 1-click terminal solutions.

⚠️ No space left on device (from dd or encclient) Expand ▾
Root Cause: The Pi SD card root partition /var/encsvc has only ~1-2 MB free space. Creating a 12 MB test file here crashes with ENOSPC.
Immediate Fix: Always run heavy tests in RAM: cd /dev/shmem and clean up flash with: rm -rf /var/encsvc/demo-out /var/encsvc/*.bin
⚠️ tr: cannot execute - No such file or directory Expand ▾
Root Cause: The QNX Neutrino 8.0 target root filesystem image does not ship with the tr binary, causing demo.sh Step 3 to abort.
Immediate Fix: Follow Phase 6 and Phase 7 by hand in /dev/shmem, or apply the POSIX word-splitting patch from the Faculty Review tab.
⚠️ REMOTE HOST IDENTIFICATION HAS CHANGED Expand ▾
Root Cause: The Raspberry Pi generates fresh SSH host keys in RAM upon every boot.
Immediate Fix (PC): ssh-keygen -R 10.0.0.1 and then reconnect and type yes.
⚠️ sh: ./encserver: cannot execute - No such file or directory Expand ▾
Root Cause: SSH opens in an empty user home folder (/home/qnxuser) instead of the project directory.
Immediate Fix: Execute cd /var/encsvc immediately after every SSH login.
⚠️ cannot reach "encsvc": No such file or directory Expand ▾
Root Cause: The server was either stopped with Ctrl+C in its window or crashed during an earlier test.
Immediate Fix: In the left window, restart with: ./encserver -v and check registration with: ls /dev/name/local/
⚠️ name_attach: Operation not permitted Expand ▾
Root Cause: Registering system-wide channel names under /dev/name/local requires root permissions on some QNX security profiles.
Immediate Fix: Run su (password: root), cd /var/encsvc, and rerun ./encserver -v.
⚠️ Could not load library libcrypto.so.3 Expand ▾
Root Cause: The binary was compiled on PC using standard make (OpenSSL mode), but the Pi target lacks the OpenSSL shared library.
Immediate Fix: On PC: make clean, then make CRYPTO=builtin, then make deploy.
⚠️ Encrypted Block differs from Reference Encryption Expand ▾
Root Cause: The client and server are using different enc.key files (a new key was generated after the server loaded the old one).
Immediate Fix: Stop the server, ensure enc.key exists in /var/encsvc, and restart ./encserver -v.

QNX-ENC v1 Header Structure

Designed for human inspectability via head -n 6 <file>.enc while preserving raw binary efficiency.

QNX-ENC v1 # Format signature
name hello.txt # Original filename
size 397 bytes # Exact original byte length
blocks 1 of up to 2097152 bytes # Total 2MB Data Blocks
iv 1 02d96ed12ec2d1706ebe75bc5a27fc23 # Fresh 16B IV per block
--- # End of header marker
<raw encrypted binary bytes: exactly 397 bytes>
💡
ADR 0002 Rationale: The format omits HMAC/MAC integrity checks intentionally. Decryption runs locally on the client with the shared key and is verified with cmp, keeping microkernel IPC paths focused on concurrency.
